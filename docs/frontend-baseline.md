# Baseline поточної поведінки фронтенду

Етап 1 [плану рефакторингу](refactoring-plan.md). Звіт складено за
результатами ручних перевірок, наданими власником проєкту; асистент
їх повторно не виконував. Це вихідна точка для порівняння наступних етапів,
а не підтвердження проходження всіх сценаріїв розділу 8 плану.

## Середовище

| Пристрій | Доступ |
|---|---|
| Chromebook, Chromium | localhost та HTTPS через Tailscale Serve |
| OnePlus Nord 5, Android | HTTPS через Tailscale Serve |

- Фронтенд — порт `8000`; Ktor API — `8080`; HTTPS-проксі API — `8443`.
- Для HTTPS-доступу внесена тимчасова зміна визначення `API_BASE_URL`
  у `frontend/app.js`. Вона є частиною середовища перевірки й **не є
  частиною рефакторингу**; у цьому етапі її не змінювали.
- Версії ОС і браузерів та назву браузера на OnePlus не зазначено.
  Інші браузери й платформи цим звітом не покриті.

Результати нижче стосуються наданого набору перевірок загалом.
Покриття кожного сценарію окремо на обох пристроях не деталізоване,
крім явно зазначених випадків.

## Працює — підтверджено ручною перевіркою

| Група | Підтверджена поточна поведінка |
|---|---|
| Запуск і навігація | Після налаштування HTTPS запуск без помилок Console; перемикання вкладок, History API, Назад/Вперед |
| Теми | Auto/Day/Night та збереження вибраної теми |
| Карта | Масштабування, поворот, 2D/3D і відображення будівель |
| GPS і LIVE | GPS-маркер, коло точності; LIVE-маркери, плавний рух і кластери |
| Мінікарта | Відкриття з Trasa та Przystanek; звичайне закриття припиняє її polling, не зупиняючи головну карту |
| Trasa | Пошук маршрутів, адреси, GPS-точки, swap, історія, розгорнуті картки, LIVE-оновлення статусів і часу |
| Przystanek | Пошук і вибір платформ, табло, автоматичні оновлення; HTTP-запити табло припиняються на прихованій вкладці |
| Звіти | Створення, голосування, скасування/зміна голосу та оновлення звіту; особливість видимості оновлення наведена нижче |
| Мобільна взаємодія | Сенсорні свайпи Trasa та Przystanek на OnePlus Nord 5; мобільні підказки, клавіатура, згортання браузера та відкриття мінікарти |

Перевірки GPS і LIVE підтверджені за доступності відповідних даних;
це не підтверджує поведінку при всіх варіантах їх відсутності.

## Проблема вже існує / зафіксована особливість

| ID | Спостереження до рефакторингу | Межі підтвердження |
|---|---|---|
| B1 | У режимі Auto зміна системної теми при відкритій мінікарті призводить до її зникнення | Стан таймерів після цього **не перевірено**; не прирівнювати до звичайного закриття |
| B2 | При активації полів основної форми `Zgłoś kanara` з'являється нефункціональна нижня форма `Zgłoś kanarów` | Підтверджено на Chromebook і OnePlus |
| B3 | У Przystanek після зміни статусу рейсу на «від'їхав» розгорнута картка закривається і більше не відкривається | Зафіксована поточна поведінка; причина цим звітом не встановлюється |
| B4 | У горизонтальній орієнтації телефона навігація й пошук перекривають більшість результатів | Поточне обмеження дизайну |
| B5 | Після оновлення власного звіту новий допис стає видимим після закриття й повторного відкриття стрічки | Оновлення звіту працює з цією особливістю відображення |
| B6 | GeolocateControl на Chromebook може спочатку сильно віддалити карту через приблизну позицію, а згодом уточнити координати | Особливість початкового визначення позиції; не свідчить про непрацездатність GPS загалом |

Ці спостереження слід відрізняти від нових регресій під час міграції.
Їх виправлення потребує окремого погодження й не входить у фіксацію baseline.

Примітка після виправлення B1: перемикання теми тепер зберігає мінікарту,
маркери й LIVE-сеанс; шари відновлюються зі збереженої геометрії.
Користувач підтвердив ручну перевірку. Початкові спостереження в таблиці
залишено як історичний baseline; B2–B6 не переглядалися.

## Не перевірено та обмеження покриття

- Початкове обмеження перевірки таймерів B1 стосується історичного baseline;
  у виправленій реалізації збереження polling покрито автоматичними тестами.
- Достовірність транспортних розкладів порівняно з іншими джерелами.
- Сценарії розділу 8 плану, не підтверджені явно в цьому звіті, залишаються
  **не перевіреними**: зокрема відмова GPS, втрата LIVE, помилки OSRM/API,
  rate limit 429 та повнота обробки мережевих збоїв.
- Точні версії браузерів, тестові маршрути/stopId/tripId, знімки й журнали
  запитів не надані; не стверджується перевірка кожного параметра API,
  відсутності всіх дубльованих запитів або повної сумісності браузерів.

Для подальшого порівняння використовуються три результати: **працює**,
**проблема вже існує**, **не перевірено**. Відсутність запису про сценарій
не означає його успішного проходження.

Етап 1 завершено фіксацією наданих результатів. Робочий код і наявні
документи в межах цього етапу не змінювалися; етап 2 не розпочато.
