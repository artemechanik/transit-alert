# transit-alert

Веб-застосунок для громадського транспорту Любліна: GTFS-розклади,
live GPS позиції транспорту та звіти користувачів про контролерів.
Інтерфейс польською мовою містить карту транспорту, планувальник поїздок,
табло відправлень із зупинок і стрічку звітів.

⚠️ Проєкт в активній розробці, структура та фічі можуть швидко змінюватись.

## Стек

- **Backend:** Kotlin 2.0.20, Ktor 2.3.12 (Netty), JVM 17, Exposed ORM,
  HikariCP та PostgreSQL. Збірка через Gradle wrapper 8.9.
- **Frontend:** HTML, CSS і vanilla JavaScript без системи збірки,
  карта MapLibre GL 4.7.1. Є вебманіфест; service worker та офлайн-кешування
  в поточному коді не реалізовані.
- **Дані:** GTFS static та GTFS-Realtime від `zbiorkom.live`.
- **Картографія:** локальні світлий і темний стилі на основі OSM Liberty,
  векторні тайли та геокодинг адрес від MapTiler. Геометрію маршруту для
  мінікарти фронтенд запитує в публічного OSRM.

## Запуск локально

Потрібні JDK 17, Docker із командою `docker compose` та Python 3 для
роздавання фронтенду. Для першого запуску потрібен інтернет: Gradle завантажує
залежності, бекенд — GTFS, браузер — бібліотеку карти й картографічні ресурси.
Node.js та встановлення npm-пакетів для запуску фронтенду не потрібні.

Команди нижче виконуються з кореня репозиторію, якщо не зазначено інше.

### 1. База даних

```bash
cd backend
docker compose up -d
docker compose ps
```

Compose запускає `postgres:16-alpine` на порту `5432`, створює базу
`transit_alert`, користувача `transit` із паролем `transit`.
Дані зберігаються в Docker volume `transit_pg_data`.

### 2. Backend

У каталозі `backend/`:

```bash
./gradlew run
```

Gradle wrapper уже є в репозиторії; встановлювати системний Gradle або
генерувати wrapper не потрібно. У Windows використовуйте `gradlew.bat`.

Сервер слухає `0.0.0.0:8080`, локальна адреса — `http://localhost:8080`.
Перед запуском HTTP-сервера `DatabaseFactory.init()` створює відсутні таблиці,
потім будується граф маршрутів. Це створення схеми, а не система міграцій БД.

Статичний GTFS імпортується автоматично фоновою задачею при першому запуску,
далі перевіряється з інтервалом 6 годин. Після імпорту оновлюються кеші й граф
маршрутів. LIVE-фід опитується з паузою 15 секунд між циклами. Поки перше
завантаження не завершилося, пошук, розклад або карта транспорту можуть
повертати порожні результати. Ручні seed-файли для запуску не потрібні.

Бекенд читає змінні середовища; без них використовує такі значення:

| Змінна | Значення за замовчуванням |
|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/transit_alert` |
| `DB_USER` | `transit` |
| `DB_PASSWORD` | `transit` |

Автоматичного читання `.env` у коді бекенда немає: змінні потрібно передати
в середовище процесу. Порт HTTP-сервера `8080` заданий у `Application.kt`.

### 3. MapTiler і frontend

В іншому терміналі, з кореня репозиторію:

```bash
cp frontend/config.example.js frontend/config.js
```

У локальному `frontend/config.js` замініть шаблон на свій клієнтський ключ:

```javascript
window.MAPTILER_KEY = 'ваш-ключ-maptiler';
```

`config.js` виключений із Git і підключається перед `app.js`. Ключ використовується
в браузері для тайлів та пошуку адрес; це не серверний секрет.

Запустіть HTTP-сервер із каталогу `frontend/`:

```bash
cd frontend
python3 -m http.server 8000
```

Відкрийте `http://localhost:8000`. Геолокація потребує дозволу браузера;
для доступу з іншого пристрою за звичайною HTTP-адресою вона може бути недоступна
через вимогу захищеного контексту.

У звичайному локальному режимі `app.js` формує адресу API як
`<протокол сторінки>://<ім’я хоста>:8080`. Окремого параметра API в `config.js`
немає. Для хостів із `trycloudflare.com` у коді є окрема жорстко задана адреса
тунелю; її працездатність тут не підтверджена. Бекенд дозволяє CORS `anyHost()`.

## Перевірки

Команди з `backend/`:

```bash
./gradlew test
./gradlew build
./gradlew buildFatJar
```

Тести в `GtfsTimeTest.kt` перевіряють час GTFS і старт пошуку, зокрема в дні
переходу на літній та зимовий час. `RoutingAlternativesTest.kt` перевіряє
транспортні альтернативи, піші ділянки й виключення рейсів.
Автоматизованих тестів фронтенду в репозиторії немає.

Після запуску бекенда можна зробити запити без зміни даних:

```bash
curl 'http://localhost:8080/stops/search?q=abra'
curl 'http://localhost:8080/live-vehicles'
curl 'http://localhost:8080/reports'
```

У браузері перевірте карту, перемикання теми, пошук зупинки у вкладці
`Przystanek` і пошук поїздки у вкладці `Trasa`. Відсутність LIVE-позицій може
бути пов’язана із зовнішнім фідом або незавершеною синхронізацією GTFS.

## Поточні обмеження

- `refreshMapMarkers()` та `drawVehicleMarker()` зараз завершуються без
  малювання. Маркери звітів на карті не слід вважати реалізованою можливістю;
  LIVE-карта транспорту працює через окремий `updateLiveCityMap()`.
- Швидка форма `sendQuickReport()` показує повідомлення без надсилання даних.
  Основна форма використовує `submitReport()` і `POST /reports`.
- `GET /reports` повертає до 100 неприхованих дописів від останньої 05:00 за
  часом Любліна. Обмеження 45 хвилин застосовується до оновлення попереднього
  допису, а не до всієї стрічки.
